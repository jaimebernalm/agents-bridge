Why two models

Different models.
Different blind spots.

One model reviewing its own work tends to agree with itself. A second model, trained differently, questions the assumptions the first one never thought to check.

  1. One finds what the other misses

    Each model has its own habits and biases. When Codex reviews Claude's plan, or Claude reviews Codex's code, mistakes that slipped past the author tend to surface.

  2. One fixes what the other breaks

    Findings go straight back to the chat that wrote the code, with the context to fix them. No copying output between windows.

  3. Disagreement is the signal

    Where they still disagree is exactly where you should look. The bridge keeps it on the record instead of forcing a consensus.

  4. Reviews with real context

    The reviewer isn't a fresh run starting from zero. It's your chat, with its history and the files it has already read.

How it works

No sessions to manage.
Just ask in plain words.

Ask either chat. From Claude or from Codex, describe what you want them to do together and the limits you have in mind.

you → claudeCollaborate with Codex on this: review the error handling in src/api and propose fixes. 20 messages, 20 minutes.

Answer three questions. Nothing is sent until you say yes, and the bridge reads your answers from the app itself.

claude asksMay Codex edit files and make local commits?› Yes How many messages and how much time at most?› 20 messages · 20 min Start with a new Codex chat?› Yes

Watch them work. The two chats message each other directly. Pause, finish or export from the panel at any time.

claude → codexReview task: the retry path in src/api/client.ts. Draft v1 attached. codex → claudeTwo defects: the timeout is swallowed in fetchUser, and retries ignore 429. 6 of 20 messages · 14 min left

Read the result. Every result and review says who wrote it and which version it refers to. Where they still disagree stays on the record.

result v2 · by claudeFix the 429 retry; surface the fetchUser timeout. review of v2 · by codexAgree on the retry. Disagree on the timeout: it is handled upstream. Disposition: proposal, with disagreements

You stay in control.
The agents don't.

The bridge reads your answers from the app itself, never from what an agent says. Text from the other agent carries no authority, whatever it says.

Install

Two commands per app.
Then just ask.

Installs as agents-bridge.

For the desktop apps on macOS. Support for the Claude Code and Codex CLIs is coming. You need Claude Desktop (Code tab, Claude Code 2.1.224 or later), Codex Desktop running, Bun 1.4 or later, and Git.

  1. 01 Install the Codex side

    codex plugin marketplace add jaimebernalm/cc-cdx-bridge
    codex plugin add agents-bridge@jaimebernalm

    In Codex, open Agents Bridge in the plugins and trust both hooks. Then open a new Codex chat.

  2. 02 Install the Claude side

    claude plugin marketplace add jaimebernalm/cc-cdx-bridge
    claude plugin install agents-bridge@jaimebernalm

    Then open a new Code chat in Claude Desktop.

  3. 03 Check that they see each other

    Open the same project folder in both apps and ask either chat: “Use Agents Bridge to list the chats in this folder.” Not listed? See Troubleshooting.
